通往超级智能的路
绕不开强化学习——
LLM 走的是捷径

Rich Sutton 在 RLC 2025 上说了一句让半个 AI 圈不舒服的话：通往真正 AI 的道路穿过强化学习，而不是大语言模型。LLM 所有重要的事情都在「设计时」完成——训练完就部署，到了真实世界它什么都不学。而 Sutton 要的恰恰相反：所有重要的事情都必须在运行时完成——在线学习、建模、规划、抽象，全部在 Agent 与世界的交互中生长出来。他花了半个世纪想这个问题，现在给出了他的答案：OaK 架构——Options and Knowledge。一个从经验中生长出超级智能的蓝图。

设计一个心智
只需要三条铁律

第一条：领域通用。Agent 的设计不应该反映它将要使用的世界。完美的 AI 设计不是一部百科全书——它应该能写在三张幻灯片上。世界的复杂性是无穷的，你不应该试图把它编码进设计里，而应该只内置能发现和捕获任意复杂性的元方法。第二条：纯经验驱动。Agent 只从运行时经验中学习，不依赖特殊的训练数据。你去上班、遇见同事、记住名字——这些都不可能在工厂里预编程。第三条：开放式抽象。Agent 能形成任何需要的概念来应对它遇到的世界，只受计算资源限制。这三条合在一起就是 Sutton 的追求：我们想要能自己发现的 Agent，而不是装着我们已发现知识的容器。

Transcript

The actual contents of minds are part of the arbitrary intrinsically complex outside world. They are not what should be built in as their complexity is endless, genuinely endless. Instead, we should build in only the meta methods that can find and capture this arbitrary complexity.

In short, we want agents that can discover like we can, not which contain what we have already discovered.

世界比 Agent 大得多
所以一切都是近似的
一切都在变

Sutton 提出了一个叫「大世界视角」的概念。世界不只是比 Agent 大一点——它大得多。世界包含数十亿其他 Agent，每个 Agent 脑子里在想什么都跟你有关。你永远不可能在脑子里装下世界的完整状态。所以一切必然是近似的：近似的值函数、近似的策略、近似的模型。更关键的是，由于你的函数近似器无法捕获所有东西，世界看起来是非平稳的——即使它的动力学并没有真的变。你今天想去厕所、明天想喝咖啡、后天想去图书馆——环境规律没变，但你的价值在变。这就是为什么运行时学习不是可选的锦上添花，而是生存的必需。

感知 → 子问题 → 选项
→ 模型 → 规划
一个无限循环

OaK 的名字来自 Options and Knowledge。一个选项（Option）就是一对：一种行为策略加一种决定何时停止的方式。Agent 拥有大量选项，而它的知识就是关于「执行某个选项后会发生什么」的高层转移模型。核心是一个五步循环——FC-STOMP：感知过程构造有趣的状态特征（Feature Construction），然后为高排名的特征创建子问题（SubTask），学习解决子问题的选项（Option），学习选项的转移模型（Model），用模型做规划（Planning）。后续步骤的反馈又会回传给特征构造——哪些特征被证明有用、哪些没有——形成一个永不停止的发现循环。八个步骤全部在运行时并行执行。

Transcript

In the Oak architecture, the agent has lots of options and its knowledge will be about what happens when you follow the option. So in this way the agent is meant to learn a high level transition model of the world that enables planning with larger jumps and hopefully carves the world at its joints.

The perception process is responsible for constructing interesting state features. The play process — problem posing and solving — that's where you do the core reinforcement learning things. And then you predict the consequences of those options to form a transition model. And then you plan with the transition model to get improved policies and values.

Agent 必须自己提问
而不是等人类出题

OaK 最大胆的主张是：子问题不能由人给定，必须由 Agent 自己创造。怎么创造？当 Agent 发现一个有趣的特征——比如一个声音、一个画面、一个触感——它就把「重新产生这个特征」变成一个子问题。Sutton 叫它「尊重奖励的特征达成子问题」：驱动世界到特征值高的状态，但不能牺牲太多主奖励。就像小猩猩荡秋千——它不是在觅食，它只是觉得那个感觉有趣，然后反复尝试控制它。虎鲸把浮标顶在背上、婴儿从一个玩具转到另一个——玩耍就是自我出题的过程。每个子问题的解就是一个选项，每个选项又生成新的特征，新特征又变成新问题——无限循环，开放式生长。

蓝图还没画完
但它可能第一次
画对了方向

Sutton 很坦诚：OaK 还没完成。两个关键问题标着红色。第一个是可靠的持续深度学习——我们能做线性情况、表格情况，但深度网络的持续学习仍然有灾难性遗忘和可塑性丧失的问题。第二个是自动生成新状态特征——这是从 1960 年 Minsky 就开始谈的老问题。反向传播本应在 1986 年解决它，但它没有。但即使不完整，Sutton 认为 OaK 第一次给出了几个根本问题的机械性回答：高层知识如何从低层经验中学到？概念从哪来？推理是什么？（也许就是用学到的模型做规划。）玩耍的目的是什么？（发现结构化认知的子问题。）感知是什么？（不依赖人类标签、从经验中生长出来的概念。）

运行时学习为什么
总是赢过设计时？

Sutton 给了四个理由。第一，设计时不可能覆盖所有情况——世界太大、太复杂、有太多不可预见的细节。你的机器人出厂后遇到的同事名字，不可能在工厂里预编程。第二，运行时学习能针对实际遇到的世界部分进行定制——你不需要知道全世界，只需要深入理解你此刻所在的角落。第三，运行时学习随可用算力扩展，而设计时学习随可用的人类专家知识扩展——历史上，随算力扩展的方法总是长期赢家，这正是「苦涩教训」（Bitter Lesson）的核心。第四，运行时学习使元学习成为可能——你尝试一种学习方式，再尝试另一种，发现哪种更好，下次就用更好的。这种「学习如何学习」的能力，只有在运行时才能实现。如果所有事情都是一次性的设计时决定，你永远无法变得更善于学习。

Transcript

Runtime learning always wins over design time because the world is much bigger than the agent. Design time can't cover every case. Runtime learning can customize to the part of the world actually encountered. Runtime learning scales with available compute whereas design time learning scales with the available human expertise.

Historically scaling with compute wins in the long run. That's what the bitter lesson is explicitly about. Runtime learning does enable meta-learning — becoming better at learning requires that you try learning one way and then try a different way and pick the better one.

FC-STOMP：
从特征到规划的五步
是 OaK 的心脏

Feature Construction：感知过程从原始观察中构造状态特征向量，每个分量代表世界的某个有趣方面。SubTask：为高排名的特征创建子问题——「驱动世界到这个特征值高的状态，同时不丢太多奖励」。Option：用离策略算法（GTD、Emphatic TD 等）解决子问题，产出一个选项（策略+终止函数）。Model：学习选项的转移模型——给定起始状态和选项，预测终止时的状态分布和累计奖励。关键洞察：选项模型的规划方程和单步动作的值迭代几乎一样，只是把 action 换成 option、单步奖励换成选项期间的累计奖励。Planning：用选项模型做值迭代来改进策略。「任何能学到的东西也能被规划」——这是 OaK 的口号。最后，规划和学习过程会产生反馈，告诉感知层哪些特征被证明有用，形成闭环。两个未解决的问题用红色标注：持续深度学习（灾难性遗忘和可塑性丧失）以及自动特征生成（表征学习的老难题）。Sutton 认为这两个问题可能在几年内被解决——届时将彻底改变深度学习的格局。
