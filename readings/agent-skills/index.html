别再造专用 Agent了
给通用 Agent 装上 Skills

过去一年里 MCP 成了 agent 连接外部世界的标准，Claude Code 证明了代码是 agent 做几乎所有数字工作的通用接口。但在实际部署中，Anthropic 反复撞上同一个缺口：agent 有智能和能力，但没有专业知识。这促使他们创建了 Agent Skills——将领域专业知识打包成有组织的文件集合，让 agent 能按需访问和应用。这篇文章解释了 Anthropic 为什么停止构建专用 agent，转而构建 skills，以及这种转变如何改变了他们对扩展 agent 能力的思考方式。

Original

A lot has changed in the past year. MCP became the standard for agent connectivity. Claude Code proved code is a universal interface for agents.

But as we've built and deployed these agents, we keep running into the same gap: agents have intelligence and capabilities, but not always the expertise to effectively tackle real work. This led us to create Agent Skills.

In this post, we'll explain why we stopped building specialized agents and started building skills instead.

代码即接口：
一个 Agent 做所有事

Anthropic 最初以为不同领域的 agent 会长得很不一样——编码 agent、研究 agent、金融 agent、营销 agent，每个都需要自己的工具和脚手架。整个行业最初也拥抱了这种「领域专用 agent」的模式。但实践中他们发现，代码不只是一个用例，而是 agent 做几乎所有数字工作的接口。以 Claude Code 生成财务报告为例：它能调用 API 做研究、把数据存在文件系统、用 Python 分析数据、综合洞察——所有这些都通过代码发生。整个脚手架变得极其简单：bash 终端 + 文件系统 + 代码解释器就够了。Claude Code 是一个编码 agent，但更准确地说，它是一个恰好通过代码工作的通用 agent。

We used to think agents in different domains would look very different. A coding agent, a research agent, one for finance, one for marketing—each seemed to need its own tools and scaffolding.

We came to see code less as just a use case and more as an interface for agents to do almost any digital work. Claude Code is a coding agent, but also a general-purpose agent that happens to work through code.

数学天才 vs 税务专家：
专业知识的缺口

谁更适合帮你报税：一个从第一性原理推导的数学天才，还是一个报过上千份税表的税务专家？多数人会选后者——不是因为他们更聪明，而是因为他们有积累的专业经验：知道哪些抵扣项常被遗漏、哪些情况会触发审计、怎样在合法范围内最大化退税。今天的 agent 就像那个数学天才：推理能力卓越，但缺乏老练专业人士的积累。它们有适当引导就能做出惊人的事情，但常常缺少关键的行业知识、最佳实践、组织流程和经验法则。Skills 通过将领域专业知识打包成 agent 可以渐进式访问和应用的格式来弥合这个缺口。

Skills 的文件结构和渐进式加载是怎么设计的？

三类 Skills 生态：
基础 · 合作 · 企业

Skills 生态由三类构成。基础 Skills 提供每个人都需要的核心能力：文档处理、电子表格、演示文稿等，编码了文档生成和操作的最佳实践。合作伙伴 Skills 是第三方公司构建的——K-Dense、Browserbase、Notion 等正在创建 Skills 来让它们的服务对 agent 可访问，把领域专业知识与服务 API 集成。企业 Skills 是组织自建的专有 Skills，编码了内部流程、合规要求和机构知识。几个新兴趋势正在塑造这个生态：早期 Skills 只是简单的文档引用，现在已经演化为协调数据检索、复杂计算和格式化输出的多步骤工作流；Skills 创建正在从工程师扩展到产品经理、分析师和领域专家——用 skill-creator 工具，30 分钟就能创建并测试第一个 Skill。

完整架构：
四层分离的 Agent 系统

把所有部分放在一起，新兴的 agent 架构由四层组成，每层有清晰的职责。推理循环（Reasoning Loop）负责思考和决策。运行时环境（Runtime）负责执行代码和操作。MCP 服务器负责连接外部系统——数据库、API、第三方服务。Skills 负责引导和提供专业知识。这种分离让系统可理解，并让每个组件独立演进。当你给这个架构添加一个 Skill 时，效果是即时的——比如前端设计 Skill 立即提升了 Claude 的前端能力，在需要时激活排版、色彩理论和动画的专业指导，不需要时完全不占用上下文窗口。

金融和医疗领域的实际部署是什么样的？

开放标准：
跨平台可移植的 Skills

为了实现这个愿景，Anthropic 正在把 Agent Skills 作为开放标准发布。就像 MCP 一样，他们相信 Skills 应该跨工具和平台可移植——同一个 Skill 无论在 Claude 还是其他 AI 平台上都应该能用。Anthropic 一直在和社区协作完善格式规范。他们设想的未来是：当有人首次使用 AI agent 时，agent已经知道你和你的团队关心什么，因为 Skills 捕获并传递了那些专业知识。随着生态增长，社区中某人构建的 Skill 可以让你的 agent 更有用，反之亦然。真正的价值来自集体知识库：捕获专业知识、跨组织传递、不断精炼——正如 Anthropic 所说，「Skill 建设者不只是工具制造者，他们是知识的策展人」。

渐进式加载：
50 → 500 → 2000+ tokens

Skills 的核心设计是渐进式披露（Progressive Disclosure），解决了一个关键矛盾：agent 可能装备数百个 Skills，但上下文窗口是有限的。解决方案是三层加载。第一层元数据：运行时只展示 YAML frontmatter 中的 name 和 description，约 50 个 token。模型据此判断是否需要这个 Skill。第二层SKILL.md 全文：如果 Claude 判断需要，它读取完整的 SKILL.md 文件，约 500 个 token——包含工作流步骤、最佳实践、关键约束。第三层参考材料：如果需要更多细节，Skill 可以包含 references/ 目录中的补充文档，2000+ token，只在明确需要时加载。这意味着你可以给 agent 装备数百个 Skills 而不会淹没它的上下文——元数据用 50 token，完整文档 500 token，参考文件 2000+ token，都是按需加载。

Original

Skills can contain extensive information. To protect the context window and make skills composable, they use progressive disclosure: at runtime, only the metadata (name and description from the YAML frontmatter) is shown to the model.

This three-tier approach means you can equip an agent with hundreds of skills without overwhelming its context window—metadata uses ~50 tokens, full SKILL.md files ~500 tokens, and reference files 2,000+ tokens and only when specifically needed.

Skills 自带脚本：
代码即工具

传统的工具有几个问题：有些说明文档写得很糟糕，模型不总能修改或扩展它们，而且经常膨胀上下文窗口。代码则相反——自文档化、可修改、不需要在上下文中常驻。Anthropic 用一个真实案例说明了这一点：他们发现 Claude 反复写同样的脚本来给幻灯片应用 Anthropic 品牌样式，于是让 Claude 把这个脚本保存为给自己用的工具。结果是一个 apply_template.py 脚本（用 python-pptx 处理幻灯片）加上一个 SKILL.md 文档（记录品牌颜色、字体、布局规范）。Skill 的说明文档告诉 Claude 用 ./apply_template.py 脚本来就地更新 pptx 文件。这是 Skills 的一个强大模式：把可复用的代码封装成 agent 可以自主调用的工具，同时保持 SKILL.md 作为何时以及如何使用这些工具的指南。

金融服务：
DCF · 可比分析 · 盈利解读

在金融服务领域，Anthropic 在 Skills 发布后立即增强了 Claude 的金融能力。这些 Skills 让 Claude 对金融专业人士更有用，覆盖了三个核心场景：DCF 模型（现金流折现估值，编码了标准假设、敏感性分析流程和行业惯例）、可比公司分析（Comparable Company Analysis，编码了筛选同业、调整倍数、处理异常值的专业知识）、以及盈利分析（Earnings Analysis，编码了解读财报、识别关键指标变化、对比市场预期的方法论）。这些 Skills 的威力在于：它们不只是给 Claude 一个「做 DCF」的指令——而是把一个资深分析师积累多年的实操知识打包成 agent 可以按步骤执行的工作流。

医疗与生命科学：
管线 · 临床 · FHIR

在医疗和生命科学领域，Anthropic 增强了 Claude 对研究人员、临床医生和医疗开发者的能力，同样通过 Skills。核心场景包括：生物信息学管线（Bioinformatics Pipelines，编码了基因组数据处理、序列比对、变异检测的标准工作流和质控步骤）、临床试验协议（Clinical Trial Protocols，编码了试验设计、终点选择、统计方法和合规要求的专业知识）、以及FHIR 开发（Fast Healthcare Interoperability Resources，编码了医疗数据交换标准的实现模式和最佳实践）。这个模式的关键洞察是：通用 agent + MCP 连接器 + 垂直 Skills 的组合，比从零构建领域专用 agent 更高效——因为推理能力是通用的，专业知识是可插拔的。
