Act 1 / Thread

thread 可以先理解成一个很小的执行工位。

一个 thread 不是一块数据，而是一个正在执行指令的小单位。你可以把它想成“这个小工位负责算某个位置的数”。GPU 厉害的地方，是能同时摆出非常多这样的小工位。

Act 1 / Block

很多 thread 会被放进一个 block，像一个小组。

CUDA 里常见的层级是 grid、block、thread。你现在只要记住：block 是一组 thread。这个小组通常一起负责数据里的某个区域，也更容易共享一些临时信息。

Act 2 / Tile

tile 不是工位。tile 是从数据里切出来的一块。

这就是最容易混的地方：thread 是执行单位，tile 是数据单位。如果原始数据是一张很大的表格，那么 tile 就是表格里的一个小矩形区域。

一个 tile
tile 是一块数据，不是一个 thread
Act 2 / 对应关系

常见的思路是：一个 block 负责一个 tile。

这句话不是硬规则，但很适合入门。你可以先把它记成：一个 thread 是小工位，一个 block 是小组，一个 tile 是这组人要处理的数据块。

Act 3 / 为什么要 tile

tile 的价值，是让数据搬运和专用硬件都更顺手。

GPU 不只是“人多”。它也很在意数据怎么从内存搬到计算单元。按 tile 搬、按 tile 算，往往更容易复用数据，也更接近 Tensor Core 这类硬件喜欢的工作方式。

Act 3 / cuTile

cuTile 就是让你更多地描述“这一块数据怎么流动、怎么算”。

传统 CUDA 更常见的入门方式，是先安排 thread 的编号和索引。cuTile 把表达层级抬高：你先写 ct.load() 取一块 tile，再对这块 tile 做计算，最后 ct.store() 写回。

load tile
compute
store tile
cuTile 先让你看见 tile 级数据流

Close / 学习顺序

你现在只需要记住四句话。

thread 是小工位。block 是小组。tile 是数据块。cuTile 是让你优先用数据块来描述 GPU kernel 的方式。等这四句话稳了，再去看 CUDA 语法和矩阵乘法，就不会一上来迷路。

Example / 传统视角

如果只是做数组加法，一个 thread 可以负责一个位置。

比如 A 和 B 两排数字相加。传统 CUDA 入门常会说：第 0 个 thread 算第 0 个位置，第 1 个 thread 算第 1 个位置。这个视角的主角是 thread。

Example / tile 视角

换成 tile 视角，你先说“这一段数据一起处理”。

tile 视角不会否认 thread 的存在。底层仍然有 thread 在干活。区别是，你写程序时先把一段数据当成一个整体，再描述这个整体要被加载、计算和写回。
