ACT I — 架构

给 AI 智能体
套上安全壳

NemoClaw 是 NVIDIA 推出的开源参考架构——它不是又一个 AI 智能体，而是智能体运行的安全壳。产品经理 Chris Murphy 在直播中解释：NemoClaw 在 OpenClaw 智能体之上加了一层开放式安全运行时，提供安全策略、网络访问控制和沙箱隔离。用户可以精确控制智能体能访问什么、能触碰什么。它支持本地推理（用 Nemotron 模型），也支持 OpenAI 和 Claude 等 API 端点。关键定位是：NemoClaw 不是要做最终产品，而是让合作伙伴和开发者在它之上构建产品。完全 Apache 2 开源，不仅公开源代码，还积极接受社区贡献。

直播原文

NemoClaw is an open reference that provides how to run an agent, for example OpenClaw, inside of an open shell, secure agent runtime that has security policies and things the user can control as far as what the agent can access on the network.

We're not trying to provide the end product. That's why it's an open-source thing. You can take it, use it for what you want, or if you're a partner, you could build on it and make a product.

路线图第一章：
把地基打牢

4-5 月的主题是核心体验加固。团队在三个方面发力：第一，安全加固——持续运行安全扫描和评估工具，确保运行时的安全边界坚不可摧。第二，跨平台安装体验——虽然 NemoClaw 理论上能在任何 Linux 上运行，但团队在特定平台上做端到端测试验证。第三，也是最大的惊喜：NemoClaw 不再只支持 OpenClaw。团队正在加入 Hermes 作为第二种智能体类型。Murphy 解释说，通过支持至少两种智能体，他们确保架构不会被锁死在某个角落，为未来支持更多智能体类型和框架打下基础。

ACT II — 体验

Jensen 的要求：
令人愉悦的体验

6-7 月的主题直接来自 NVIDIA CEO 黄仁勋的要求：「令人愉悦的用户体验」。Murphy 坦言目前仍处于 alpha 阶段，安装和使用体验还有很多摩擦。这个阶段要解决的核心矛盾是：极其灵活强大的技术和合理的安全约束之间的张力。具体包括：扩展消息服务和提供商集成、本地推理性能优化、多 GPU 支持、多智能体工作流、以及更好的安全策略预设——让用户不再觉得「给智能体套了个钢笼」。Murphy 强调 NVIDIA 还在大量投入上游 OpenClaw 社区的安全改进工作，因为依赖关系意味着上游进展直接影响 NemoClaw 的体验。

企业级扩展：
安全与能力的博弈

8-9 月的主题是企业级扩展。Murphy 透露团队内部也在亲身经历这个挑战——把 NemoClaw 接入 NVIDIA 自己的企业数据。最大的难题是：如何让安全部门签字批准一个自主进化的智能体？因为智能体能做的事情几乎是无限的，传统的安全审批流程根本无法覆盖。团队发现了一个关键区分：开发阶段和部署阶段需要完全不同的安全模型。开发时可以在隔离环境中放开所有能力让智能体自我进化；但部署实际用例时，必须用安全策略严格限制它只能做你需要它做的事。

不是「对比」，
是「加法」

直播中被问得最多的问题是「NemoClaw vs OpenClaw」。Murphy 的回答很直接：这个问题本身就问错了。NemoClaw 和 OpenClaw 不是竞争关系，而是叠加关系。OpenClaw 是智能体本身，NemoClaw 在上面加了安全层、策略层、安装工具和版本验证。同样的逻辑也适用于 Claude Code 和 Codex 的对比——NemoClaw 可以和这些工具配合使用。每种智能体都有自己擅长的场景。OpenClaw 的优势在于智能体记忆和随时间学习的能力，这是一些用户选择它而非 Codex 或 Claude Code 的原因。NVIDIA 的目标不是选赢家，而是赋能整个生态。

It's not NemoClaw versus OpenClaw. You can run NemoClaw with OpenClaw. So you're adding the securities and the policy layers. It's not a versus, it's a plus.

开发阶段：
放开所有限制

Murphy 描述了企业部署的第一阶段：在隔离环境中放开智能体的全部能力。你可以在一个独立的虚拟机或离线设备上运行智能体，让它自由地自我进化、学习新技能、构建能力。这个阶段不需要安全部门的签字——因为智能体被物理隔离了，不接触生产网络和敏感数据。这就像一个沙盒训练场：智能体在这里变得强大，积累技能和知识。NVIDIA 内部也是这么做的——先在隔离环境中验证智能体的能力，确认它能完成预期任务，然后才进入下一阶段。

部署阶段：
精确锁定边界

第二阶段是将训练好的智能体部署到真实环境。此时安全策略变得至关重要。Murphy 指出核心挑战：自主进化的智能体理论上能做的事情是无限的，但安全部门需要签字确认风险可控。解决方案是从「能做任何事」收缩到「只能做你需要它做的事」。NemoClaw 的安全策略层让用户可以精确控制：哪些网络可以访问、哪些工具可以使用、哪些数据可以触碰。这不仅仅是企业的需求——即使是个人和家庭场景，你可能也想让孩子能使用某些功能但不能使用其他功能。多租户后端也在路线图上，支持不同用户以不同权限使用同一个智能体。
