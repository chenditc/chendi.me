03 / SKILL

不是全量加载，
而是路由匹配

Skill 不一样，它并不会每一次都加载所有的内容。它更像模型内部的 MoE（混合专家）架构：Skill 的描述相当于在做多专家的 Routing（路由），而每一个 Skill 的内容则对应一个具体的专家。只有被匹配到的 Skill 才会激活。

04 / 强化学习

能不能让 Skill
自己学会？

理解了 Claude.md 和 Skill 的区别之后，一个自然的想法出现了：能不能用 Skill 作为人类经验的承载，设计一个流程，让它像强化学习一样，自动地把经验积累下来？

具体来说就是——添加一个 Skill，让模型执行，观察结果，把缺失的地方补回 Skill 里，形成一个闭环。

第三幕

指令的边界

05 / 衰减

塞得越多，
遵循率越低

但实际做下来发现了一个关键问题：记录到 Skill 里的信息，模型不一定会完全遵循。 而且模型对指令的遵循度会随着指令数量和复杂度的增加而变差。你往 Skill 里塞得越多，指令遵循率反而越低。

所以单纯"加 Skill"这个动作并不够。你还得同时检验模型的遵循情况，根据实际的遵循程度做进一步优化。说白了，这个过程其实和我们之前做提示词工程（Prompt Engineering）就非常像了。

越多 ≠ 越好

06 / 结论

越简单，
越能规模化

想清楚这些之后，结论是：这个让 Skill 自我学习的循环，应该越简单越好。

方法要简单——本质上就是一个循环 Loop：执行、检验、修正、再执行。

工具也要简单——只用文本作为记录的工具。Skill 本身就是文本，而且它比较容易被唤起和调用，天然适合做这个载体。

简单 × 算力 = 规模化

循环越简单，才越容易规模化。剩下的交给算力和可校验的环境就好。
